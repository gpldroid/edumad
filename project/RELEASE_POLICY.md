# سياسة الإصدارات والتغييرات

**المشروع:** كتاب «العبودية المعاصرة» — عماد لمراني  
**النطاق:** المخطوط، قارئ HTML، ملفات التوثيق، وإعدادات النشر.

## 1. مصدر الحقيقة
- `CHANGELOG.md` هو سجل التغييرات التاريخي المختصر.
- `project/PROGRESS.md` يصف حالة الإنجاز الحالية وما تبقى.
- `project/EDITORIAL_REVIEW_REPORT.md` يسجل نتائج التدقيق والملاحظات التي لم تُغلق.
- نصوص المخطوط في `manuscript/` هي مصدر محتوى الكتاب.
- لا يُعد نجاح GitHub Actions دليلاً على اكتمال المراجعة العلمية، ولا يُعد وجود ملف في المستودع دليلاً على اعتماده.

## 2. ترقيم الإصدارات
يتبع المشروع صيغة `MAJOR.MINOR.PATCH`، مع البقاء في مرحلة ما قبل الإصدار النهائي:
- **0.MINOR.PATCH**: إصدارات تطويرية قبل اعتماد الكتاب. الرقم 0 يعني أن المحتوى والبنية لم يصلا بعد إلى اعتماد نهائي.
- **PATCH** (مثل 0.1.1): تصحيحات إملائية أو تنسيقية أو روابط أو أخطاء لا تغير الحجة أو بنية الفصل.
- **MINOR** (مثل 0.2.0): إضافة فصل أو مبحث أو مصدر موثق، أو مراجعة جوهرية داخل البنية المعتمدة دون تغييرها جذرياً.
- **MAJOR** (مثل 1.0.0): أول إصدار نهائي معتمد، أو تغيير لاحق يكسر توافق البنية/الفهرس أو يعيد تشكيل الكتاب بشكل جوهري.

لا تُستخدم أرقام الإصدارات كعداد لكل commit. كل commit يسجل العمل، أما الإصدار فيمثل مجموعة تغييرات متماسكة تم التحقق منها.

## 3. متى يصدر الإصدار 1.0.0؟
لا يصدر الإصدار النهائي إلا بعد:
1. تثبيت الفهرس النهائي ومطابقة عناوين الأبواب والفصول.
2. مراجعة المقدمة والفصول 1–22 والخاتمة مراجعة تحريرية وعلمية ولغوية.
3. التحقق من جميع الاقتباسات والإحصاءات والتواريخ والمراجع والروابط والطبعات والصفحات.
4. حل الملاحظات الجوهرية المفتوحة أو توضيحها.
5. اعتماد المؤلف للنص النهائي.
6. إنتاج PDF نهائي ومراجعته بصرياً، وتثبيت بيانات الكتاب وحقوقه.
7. اختبار قارئ HTML وروابط الفصول والطباعة/حفظ PDF.
8. نجاح نشر GitHub Pages والتحقق من الرابط المنشور.

عدد الصفحات المستهدف نحو 400 صفحة إرشادي، وليس معياراً لزيادة النص أو تكراره. يُسجل العدد الفعلي بعد التنضيد.

## 4. قواعد كل تغيير
- التغيير الصغير والمحدد يفضّل أن يكون في commit مستقل.
- لا تستبدل نصاً أصلياً بمسودة معاد بناؤها دون حفظ الأصل وتوثيق المقارنة.
- ميّز بوضوح بين: نص أصلي محفوظ، وإعادة بناء تحريرية، ومسودة، ونص معتمد.
- لا تضف مرجعاً لمجرد ملء القائمة؛ تحقق من وجوده وبياناته وصلته بالادعاء.
- لا تضع بيانات اعتماد أو أسراراً أو مفاتيح API في Git.
- حدّث `CHANGELOG.md` في نفس دفعة العمل التي تتضمن التغيير.
- حدّث `PROGRESS.md` عند تغير حالة الإنجاز، لا لمجرد كل تعديل شكلي.
- لا تدّع نجاح النشر أو الاختبار دون نتيجة فعلية من GitHub Actions أو فحص الموقع.

## 5. صيغة رسائل Commit
استخدم بادئات واضحة:
- `content:` إضافة أو مراجعة نص المخطوط.
- `edit:` تحرير لغوي/أسلوبي.
- `cite:` إضافة أو تصحيح توثيق.
- `site:` تعديل قارئ HTML أو CSS/JS.
- `docs:` تحديث الوثائق والسجلات.
- `fix:` إصلاح خلل.
- `release:` تجهيز إصدار.

مثال: `edit: revise chapter 05 terminology and citations`.

## 6. إجراء إصدار جديد
1. راجع كل عناصر `[Unreleased]` في CHANGELOG.
2. تحقق من الملفات والروابط والبناء والنشر.
3. حدّث رقم الإصدار والتاريخ في سجل التغييرات وبيانات الإصدار عند وجودها.
4. أنشئ Git tag بصيغة `vX.Y.Z` فقط بعد تحقق الشروط.
5. اكتب ملخص إصدار يذكر التغييرات والقيود المعروفة.
6. احتفظ بسجل الإصدارات السابقة دون إعادة كتابة التاريخ.

## 7. مراجعة واعتماد المؤلف
التغييرات التحريرية الجوهرية التي تمس الأطروحة أو الاستنتاجات أو ترتيب الكتاب تُعرض على المؤلف للاعتماد قبل إعلانها نسخة نهائية. ويظل المؤلف صاحب القرار النهائي في اعتماد الكتاب ونشره.
